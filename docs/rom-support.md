# Multi-ROM support

LADXR originally targeted a single ROM: the English v1.0 release of
*The Legend of Zelda: Link's Awakening DX*. It now also supports the French
(France) Rev 1 ROM, with the same features, through a **ROM profile** system.

| Profile | ROM | SHA-1 |
|---|---|---|
| `en` | Legend of Zelda, The - Link's Awakening DX (USA, Europe) v1.0 | `d90ac17e9bf17b6c61624ad9f05447bdb5efc01a` |
| `fr` | Legend of Zelda, The - Link's Awakening DX (France) (Rev 1) | `b5e4df1a67432c609fa0f23519315297c6dcdc1d` |

## Using it

The profile is detected automatically from the ROM:

```sh
python3 main.py zelda.gbc
```

You can force it (a mismatch with the ROM is reported as an error):

```sh
python3 main.py zelda.gbc --romprofile fr
```

The web UI accepts both the English (`89122269`) and French (`89757956`)
checksums.

## Architecture

The randomizer is split into a ROM-independent part (logic, item pool, item
placement, spoiler) and a ROM-facing part (patches, pointer tables, text). Only
the ROM-facing part knows about ROM revisions, through `romprofile.py`.

* `romprofile.RomProfile` holds the per-ROM data: patch address map, identical
  banks, pointer table configs, code symbols and code address map. The English
  profile is an identity profile, so its behaviour is unchanged.
* `rom.py` translates every `rom.patch(bank, addr, ...)` through the active
  profile. For non-English profiles the `old` byte assertion is relaxed (the
  bytes legitimately differ between revisions).
* `romTables.py` builds every pointer table from the profile's table config
  (e.g. the French text bank table lives at `0x1C:0x841` instead of
  `0x1C:0x741`).
* `assembler.py` tags assembled code (`codebytes.Code`); `rom.py` then rewrites
  its absolute 16-bit operands. Addresses below `0x4000` resolve against the
  fixed bank 0, the others against the patch site's bank.
* `utils.setLanguage()` / `french.py` handle the French font encoding, item
  names and dynamic message translation.

The English output is protected by a golden master: generating with the same
seed and settings must be byte-for-byte identical to the pre-refactor output.

## `rommap_fr.json`

The French mapping is generated by the Phase A tooling and committed (it
contains addresses only, never ROM bytes). It has five sections:

```json
{
  "rom": { "en_sha1": "...", "fr_sha1": "..." },
  "identical_banks": ["0a", "0b", "..."],
  "stats": { "exact": 621, "fuzzy": 72, "...": 0 },
  "patches": [
    { "file": "patches/core.py", "line": 11, "bank": 2,
      "en_addr": 7457, "region_len": 27, "fr_addr": 7489,
      "status": "exact", "candidates": 1, "executed": true }
  ],
  "tables": {
    "config":     { "texts": { "pointers_bank": 28, "banks_addr": 2113, "...": 0 } },
    "notes":      { "texts": { "banks_addr": { "en": 1857, "fr": 2113 } } },
    "validation": { "texts": { "status": "ok", "count": 688 } }
  },
  "symbols": {
    "labels": { "Farcall": { "en": 3031, "bank": 0, "fr": 3015, "status": "predicted" } },
    "inline_refs": { "763b": 3 }
  },
  "code_addrs": {
    "addrs": { "00:0b0b": { "fr": 2811, "status": "exact" } },
    "stats": { "exact": 141, "fuzzy": 45, "...": 0 }
  }
}
```

### Patch statuses

| Status | Meaning |
|---|---|
| `identical` | Bank is byte-identical, address unchanged |
| `exact` | Signature found uniquely (or disambiguated by context/order) |
| `low_entropy` | All-same-byte region (LADXR scratch/vectors); address kept |
| `translated_old` | Resolved by translating the signature's operands/pointers |
| `predicted` | Address inferred from the block address shift, verified |
| `windowed` | Best local similarity match within a window |
| `fuzzy` | Bytes differ (engine revision); best anchor match |
| `same_addr` | Short signature mostly matches at the same address |
| `not_found` / `unknown` | Unresolved, fall back to the English address |

## Adding a new ROM version or language

1. Put the target ROM in `disassembly/` and add its SHA-1 to
   `romprofile.ROM_SHA1` (and to `tools/common.py`).
2. Disassemble it (optional but useful for ambiguous cases):

   ```sh
   mgbdis.py "your-rom.gbc"
   ```

3. Generate the address map:

   ```sh
   python3 tools/instrument_en.py     # instrument an English run (settings matrix)
   python3 tools/relocate.py          # writes rommap_<lang>.json + queues
   python3 tools/tables_fr.py         # pointer table discovery (adapt the script name)
   python3 tools/symbols_fr.py
   python3 tools/code_addr_fr.py
   ```

4. Review `tools/data/manual_queue.jsonl` (unresolved) and
   `tools/data/review_queue.jsonl` (heuristic). Resolve them with the
   disassembly or by extending the relocation rules.
5. Add the language to `romprofile.py` and, if the font differs, add an
   encoding/translation module like `french.py`, wired through
   `utils.setLanguage`.
6. Run the checks:

   ```sh
   tools/check_golden_en.sh
   python3 tools/check_fr_profile.py
   tools/check_fr_generation.sh
   python3 tools/check_fr_text.py
   tools/run_tests.sh
   ```

## Current limitations

* `roomInfo.py` base addresses are not relocated, so `--exportmap` is not
  available for non-English ROMs yet.
* One patch site and one injected-code operand are unresolved and fall back to
  the English address.
* Bingo board labels and the ending credits are generated from hardcoded tile
  data and are not localized.
* Gameplay correctness must be validated in an emulator; the automated checks
  only cover structure, non-regression and placement parity.
